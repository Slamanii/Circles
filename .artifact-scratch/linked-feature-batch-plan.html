Build order

01 Account types Done ▸

New users.account_type column — user, artist, host, vendor, or venue, default user. Picked at signup via a chip row on CreateAccountScreen.tsx, validated and written server-side in loginOrSignup.

02 Event categories Done ▸

events.category — movie, professional, concert, birthday, sports, educational, private, or other. Picking other reveals a custom_category field, capped at one word, 15 characters, enforced on both the client and in createEvent.

  • Private events are excluded from every browse query (fetchEvents's .neq("category", "private")) and only open via an invite_token passed as a query param to GET /api/event/:id.
  • Movie events only may attach one video_url and carry up to five images in flyer_card; every other category is capped at one flyer image.
Changed from the original plan Swapped political for professional and added sports / educational. The movie-video field ended up singular (video_url), and it's flyer_card that became the array — carrying several images only for a movie event, not the video field.
03 Group & Free ticket tiers Done ▸

Two new tier types alongside Base / VIP / VIP++, each a plain ticket_tiers row like the others:

  • Group — group_ticket (an integer ≥ 2) records how many people one ticket admits.
  • Free — free = true forces price to 0 and skips the payment terminal entirely; a new POST /api/claim-free-ticket reserves and immediately activates the collectible.

TierTabSwitcher always shows Base/VIP/VIP++ (dimmed if absent) but only adds a Group or Free tab when the event actually has one.

04 Event Edit infrastructure Done ▸

Nothing let a creator edit an event after creation. New PUT /api/event/:id → updateEvent(), creator-only, scoped to event_date and venue — tiers, price, and supply stay fixed, since they're baked into the on-chain max_supply and the already-minted collectible rows with no live recomputation path.

Every ticket holder with status active gets notified (event_updated, a new notification type) whenever venue or date changes. New eventEditScreen.tsx, reached from an Edit icon on the creator-only stats screen.

05 Guest list Done ▸

events.guest_list — free text, never on-chain, capped at 15 names. Both the create sheet and the edit screen show fifteen fixed name fields rather than one open text box.

On the event-details screen it renders as a closed "Guest List (N)" row; tapping it reveals every name as a pill, stacked one per line.

Changed from the original plan Originally scoped as creator-only and hidden from the public page. It's now shown on the event-details screen itself, and entry moved from one freeform field to a fixed 15-slot form on both sheets.
06 Collaborators Pending ▸

New event_collaborators table, added by user id through the Edit screen, purely decorative — no edit authority. Renders as avatar chips on the event page, each linking to that person's profile. Reuses the existing GET /api/search-users endpoint for lookup.

07 Cancel event Pending ▸

Uses the cancelled status already in the events.status check constraint but never set by any code path. A new cancellation_notice field holds the creator's compensation disclosure. Purchases and scans get blocked; the ticket itself stays visible, showing the notice — cancel, not delete.

08 QR-scan access grants + scan screen Pending ▸

TicketQRScreen.tsx already encodes an asset id with nothing on the other end. New event_scan_grants table (creator-granted, per event), a POST /api/validate-ticket endpoint, and a camera-based ScanTicketScreen.tsx that shows "Group of N" when the scanned ticket's tier calls for it.

09 Host footer on event & ticket detail Pending ▸

Extend the event-detail and collectible queries to join the creator's avatar and display name, and add a footer row linking to their profile on both screens.

10 Wallet chart library swap Pending ▸

Replace react-native-chart-kit with react-native-gifted-charts in Chart.tsx — a pure rendering swap, since fetchChartData already pulls real CoinGecko price data.

11 Calendar view Optional — cut first ▸

A month grid marking days with events, tapping a day to list them. Nothing else in this plan depends on it — the first thing to drop if time runs short.

12 Story comments + share Pending ▸

No new chat message type, no 1:1 messaging — scrapped in favor of keeping story interactions self-contained. Story likes already work; new story_comments (with one level of replies) and story_comment_likes tables add comments, opened from a count next to the existing like button. Share opens the native OS share sheet — no backend change needed.
